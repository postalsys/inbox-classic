Decided

Setup file (#1)

  • Passwords, sign-in tokens and private keys only when the file has a passphrase; then the whole file is encrypted.
  • Carries settings, accounts, sign-in apps, contacts with groups, OpenPGP keys, message rules and trusted senders.
  • Import shows what the file holds and lets you choose parts and accounts.

Languages (#2)

  • All 21 offered at once, not marked as beta.
  • Drafted translations, marked for review in the catalogs, edited later.
  • The full help in every language.

All Sent and All Drafts (#6)

  • As All Inboxes: rows after it, a row per account under each.
  • Sent Items and Drafts leave the account headings (two or more accounts).
  • A draft opened from All Drafts opens in its own account.

Attachments (#9)

  • A native strip under the header: icon, name, size. Double-click or Enter opens.
  • Files that can run code are never opened, only saved.
  • A decrypted attachment opens too; the first time a note says it is stored decrypted while open.

The setup file

Export and import

#1

Export

  • File > Export > Setup...
  • Choose the parts; optional passphrase typed twice (8 characters or more)
  • One file: Name.inboxclassic, encrypted with Argon2id and ChaCha20-Poly1305 when it has a passphrase

Import

  • File > Import > Setup..., and on the first run from Add Mail Account
  • The passphrase when asked, then what the file holds with a check box each
  • Accounts already here are skipped; contacts merge; settings replaced; keys follow the changed-key rule

Stays out

  • Messages (they download again)
  • Window positions, open folders, agents' permissions
  • Caches

How each pull request is done

  1. The core and its tests: unit tests, e2e_core against ImapKit, fuzz targets for the setup file.
  2. The C API, then the three apps.
  3. The words in every language and the help.
  4. UI end-to-end steps on all three platforms, with the feature map's entries.
  5. UX review from the screenshots as a principal UX, mail app UI and product expert: light and dark, narrow, keyboard only, the longest languages; fix and look again until nothing is left.
  6. /simplify with the maintainability check.
  7. /security-review: the setup file is untrusted input that carries secrets; opening attachments is the classic way in.
  8. fmt, clippy, tests, prettier, the shells check; push, CI green, merge; the board post moves to started, then completed.
