Inbox Classic on Omarchy

Today Linux gets a .deb, the apt repository and a Flatpak manifest. Nothing installs on Arch. The goal: someone who just installed Omarchy finds Inbox Classic in the Omarchy menu, and its updates come with Omarchy's own. The route is Omarchy's own package repository; the AUR follows for plain Arch once its registration reopens.

How a package gets into Omarchy

pkgs.omarchy.org comes first in Omarchy's pacman.conf. It already carries outside apps (1password, bitwarden, dropbox, localsend, LM Studio), and its README invites package PRs. Packages are signed with Omarchy's key and appear under Install › Package, the menu Omarchy recommends over the AUR.

Seven pieces

The work

  1. The PKGBUILD

    linux/arch/PKGBUILD
    • Source tarball of the tag; cargo fetch --locked, cargo build --frozen --release; the same files as the .deb, without the apt source.
    • Depends on gtk4 libadwaita webkitgtk-6.0 and the rest, checked by namcap; gnome-keyring optional.
    • Built locally with omarchy-pkgs' own bin/build, then installed in a clean Arch container and run with --version.

  2. CI job on Arch

    .github/workflows/ci.yml · job arch
    • Build linux/ and run the UI end-to-end test under Xvfb with Arch's newest GTK and WebKitGTK.
    • makepkg of the PKGBUILD from the checkout and namcap, so a release never turns red in Omarchy's bot.
    • Non-blocking for a few weeks, then required.

  3. Omarchy desktop VM

    scripts/omarchy-vm.sh · VMware Workstation on andri@10.8.0.8
    • The checklist below, with the locally built package, before the PR.

  4. PR to Omarchy's repository

    omacom-io/omarchy-pkgs · pkgbuilds/inbox-classic/
    • PKGBUILD plus .omarchy/package.json: "release_ring": "fast" and a GitHub watch on postalsys/inbox-classic.
    • A short description: what it is, how it was tested on Omarchy 4.5, why fast ring.
    • You read it before it is opened from andris9.

  5. Following releases

    scripts/release.sh
    • Prints the link to the bot's PRs for inbox-classic. A dependency change goes to omarchy-pkgs as its own PR with pkgrel bumped.

  6. Help, README, docs

    pe-html/src/help.html · README.md · CLAUDE.md · docs/cross-platform-plan.md
    • The help's Linux removal line names only apt; add sudo pacman -R inbox-classic.

  7. Homepage

    ../inboxclassic.com
    • An "Omarchy" card beside the apt one: Install › Package, sudo pacman -S inbox-classic.
    • An "Omarchy" link beside "Install with apt" under the Linux download buttons.
Real desktop, real tiling

Omarchy in VMware on the Windows laptop

The laptop (Core Ultra 9, 24 cores, 32 GB) already has VMware Workstation, with Hyper-V on. It runs the official x86_64 ISO, the platform most Omarchy users have. The VM is reached through the laptop over SSH, so a locked or disconnected Windows session does not matter.

Setup

  • Trial first: Hyprland with 3D in VMware under Hyper-V. Fallback: software rendering.
  • One install at the VMware console over RDP, enable SSH, snapshot clean.
  • vmrun -T ws start … nogui; guest SSH via ssh -J andri@10.8.0.8.
  • Screenshots with grim in the guest, windows moved with hyprctl.
  • About 8 GB and 6 cores, running only for checks.

When

  • Before the PR: the local build via pacman -U.
  • After publishing: Install › Package › inbox-classic from clean.
  • After the next release: omarchy-update brings it.

Checklist

  • Launcher entry, icon, app id com.inboxclassic.InboxClassic
  • Passwords kept across a restart, no keyring prompt
  • Tray icon in the bar, its menu, hide to tray
  • New-mail notification; a click opens the message and raises the window
  • Code notification next to Omarchy's own code detection
  • Outlook.com sign-in through Chromium and back
  • Compose, message windows, Options, Add Account, file dialogs, Print under tiling
  • Light and dark Omarchy themes
  • mailto: from Chromium opens compose

What could go wrong

Risks

RiskAnswer
Omarchy's maintainers decline the package or keep it waitingThe repository invites PRs and carries other outside apps, but it is their call. Fallback: the AUR with the same PKGBUILD, found under Install › AUR.
Source build time on their 4 vCPU aarch64 runnersLikely 20 to 40 minutes with thin LTO. Ask in the PR; a -bin package from our .deb is the fallback.
Rolling release changes GTK or WebKitGTK; a release then fails to build thereThe CI job builds against current Arch on every PR, before a release.
Hyprland 3D in VMware under Hyper-VTrial first; software rendering is slower but enough for checks.
The laptop is also the Windows build machine and sometimes unreachableThe VM runs only for checks; phases 1 and 2 do not need it.
