Die Verbindungen von Inbox Classic

Wohin Inbox Classic Verbindungen aufbaut und warum, für technisch Interessierte.

  • Ihre Mailserver, über IMAP zum Lesen und SMTP zum Senden von E-Mails. Die Verbindungen sind mit TLS verschlüsselt, und das Zertifikat jedes Servers wird anhand der Zertifikate geprüft, denen Ihr System vertraut. Inbox Classic lehnt einen Server ohne Verschlüsselung ab, es sei denn, Sie wählen und bestätigen das.
  • Beim Hinzufügen eines Kontos sucht Inbox Classic Serverdaten über MX- und SRV-Abfragen mit DNS over HTTPS (Cloudflare, dann Google). Normale Servernamen löst das System auf. Zusätzlich werden Autoconfig-Daten des Anbieters und die Thunderbird-Anbieterliste abgefragt; dabei kann Ihre E-Mail-Adresse übermittelt werden. Exchange Autodiscover erhält Ihr Passwort nur nach einer Basic-Anmeldeaufforderung über HTTPS. Unsichere Servereinstellungen werden nicht automatisch gewählt.
  • Anmeldung über den Browser, mit OAuth 2.0 und PKCE, bei Google, Microsoft oder dem Anbieter Ihrer Anmelde-App. Der Browser kehrt nur zu Inbox Classic auf diesem Computer zurück.
  • Markenlogos (BIMI), von der HTTPS-Adresse der Marke, wenn die Nachricht das Logo nicht enthält und keine gespeicherte Kopie verwendet werden kann. Heruntergeladene Logos werden auch nach einem Neustart wiederverwendet. Die Nachricht muss die DMARC-Prüfung Ihres Mailservers bestanden haben, und der Server muss das Logo freigegeben haben.
  • Bilder aus dem Internet, wenn Sie sie ausdrücklich erlauben oder automatische Downloads beziehungsweise vertrauenswürdige Absender eingerichtet haben. In verschlüsselten Teilen ist immer eine ausdrückliche Freigabe nötig.
  • Abbestellen, nur wenn Sie darauf klicken. Eine Ein-Klick-Anfrage (RFC 8058) wird erst nach Ihrer Bestätigung gesendet. Ihr Mailanbieter muss eine gültige DKIM-Signatur bestätigen, die beide Abmeldekopfzeilen einschließt.
  • Verschlüsselungsschlüssel werden gesucht, wenn beim Verschlüsseln ein Empfängerschlüssel fehlt oder Sie eine Schlüsselsuche anfordern. Bei einer Suche nach E-Mail-Adresse wird zuerst deren Domain befragt (Web Key Directory), bei Bedarf anschließend keys.openpgp.org, sofern diese Suche aktiviert ist. Dabei wird die gesuchte Adresse übermittelt. Suchen Sie nach einem Fingerabdruck oder einer Schlüssel-ID, wird stattdessen diese Kennung an keys.openpgp.org gesendet. Beim Veröffentlichen werden öffentliche Schlüsseldaten und die zu bestätigenden Adressen übertragen.
  • Updates, von inboxclassic.com, um nach neuen Versionen zu suchen, sofern automatische Prüfungen aktiviert sind.

Anmeldecodes werden nur angeboten, wenn die Kopfzeile Authentication-Results Ihres Anbieters besagt, dass eine gültige DKIM-Signatur die relevante Domain oder deren übergeordnete Domain bestätigt. Dafür ist keine eigene Verbindung nötig.
