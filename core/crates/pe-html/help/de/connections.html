Die Verbindungen von Inbox Classic

Wohin Inbox Classic Verbindungen aufbaut und warum, für technisch Interessierte.

  • Ihre Mailserver, über IMAP zum Lesen und SMTP zum Senden von E-Mails. Die Verbindungen sind mit TLS verschlüsselt, und das Zertifikat jedes Servers wird anhand der Zertifikate geprüft, denen Ihr System vertraut. Inbox Classic lehnt einen Server ohne Verschlüsselung ab, es sei denn, Sie wählen und bestätigen das.
  • Beim Hinzufügen eines Kontos, um seine Server zu finden. Inbox Classic liest die DNS-Einträge Ihrer Domäne über DNS over HTTPS (Cloudflare, dann Google), nie über unverschlüsseltes DNS. Außerdem versucht es die Autoconfig-Datei Ihres Anbieters und die Anbieterliste von Thunderbird (ISPDB). Für Exchange fragt es Microsoft Autodiscover, das Ihr Passwort nur erhält, wenn es über HTTPS danach fragt. Ein Server ohne Verschlüsselung wird nie gewählt.
  • Anmeldung über den Browser, mit OAuth 2.0 und PKCE, bei Google, Microsoft oder dem Anbieter Ihrer Anmelde-App. Der Browser kehrt nur zu Inbox Classic auf diesem Computer zurück.
  • Markenlogos (BIMI), von der HTTPS-Adresse der Marke, wenn die Nachricht das Logo nicht mitbringt, einmal pro Start von Inbox Classic. Das geschieht nur, wenn Ihr Mailserver die DMARC-Prüfung der Nachricht bestanden und das Logo freigegeben hat.
  • Bilder aus dem Internet, nur wenn Sie sie anfordern.
  • Abbestellen, nur wenn Sie darauf klicken. Eine Ein-Klick-Anfrage (RFC 8058) wird nur gesendet, wenn die Liste die Nachricht mit DKIM signiert hat.
  • Updates, von inboxclassic.com, um zu sehen, ob eine neue Version erschienen ist.

Anmeldecodes werden nur angeboten, wenn die Kopfzeile Authentication-Results Ihres Anbieters besagt, dass die Domäne die Nachricht signiert hat (DKIM). Dafür ist keine eigene Verbindung nötig.
