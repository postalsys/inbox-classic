З’єднання, які встановлює Inbox Classic

Куди й навіщо під’єднується Inbox Classic, для тих, кого цікавлять технічні подробиці.

  • Ваші поштові сервери: через IMAP, щоб читати пошту, і через SMTP, щоб надсилати її. З’єднання шифруються за допомогою TLS, а сертифікат кожного сервера перевіряється за сертифікатами, яким довіряє ваша система. Inbox Classic відмовляється від сервера без шифрування, якщо ви не виберете і не підтвердите це.
  • Коли ви додаєте обліковий запис, щоб знайти його сервери. Inbox Classic читає записи DNS вашого домену через DNS over HTTPS (Cloudflare, потім Google), ніколи через звичайний DNS. Він також пробує файл autoconfig вашого провайдера й список провайдерів Thunderbird (ISPDB). Для Exchange він звертається до Microsoft Autodiscover, який отримує ваш пароль лише тоді, коли запитує його через HTTPS. Сервер без шифрування ніколи не вибирається.
  • Вхід через браузер з OAuth 2.0 і PKCE до Google, Microsoft або провайдера вашого застосунку для входу. Браузер повертається до Inbox Classic лише на цьому комп’ютері.
  • Логотипи брендів (BIMI) з HTTPS-адреси бренду, коли повідомлення не містить логотипа, один раз за кожен запуск Inbox Classic. Це відбувається, лише коли ваш поштовий сервер пропустив повідомлення через перевірку DMARC і схвалив логотип.
  • Зображення з інтернету, лише коли ви їх запитуєте.
  • Скасування підписки, лише коли ви його натискаєте. Запит в один клік (RFC 8058) надсилається, лише коли список підписав повідомлення за допомогою DKIM.
  • Ключі шифрування, лише коли ви шифруєте для того, чийого ключа у вас немає: спершу власний домен його адреси (Web Key Directory), потім keys.openpgp.org, якщо ви цього не вимкнули. Надсилається лише адреса.
  • Оновлення з inboxclassic.com, щоб дізнатися, чи вийшла нова версія.

Коди входу пропонуються, лише коли заголовок Authentication-Results вашого провайдера вказує, що домен підписав повідомлення (DKIM). Для цього окреме з’єднання не потрібне.
