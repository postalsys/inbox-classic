Les connexions établies par Inbox Classic

Où Inbox Classic se connecte, et pourquoi, pour mieux comprendre les échanges avec les serveurs.

  • Vos serveurs de messagerie, en IMAP pour lire le courrier et en SMTP pour l'envoyer. Les connexions sont chiffrées avec TLS, et le certificat de chaque serveur est vérifié d'après ceux auxquels votre système fait confiance. Inbox Classic refuse un serveur sans chiffrement, sauf si vous choisissez et confirmez.
  • Quand vous ajoutez un compte, pour trouver ses serveurs. Pour rechercher les enregistrements MX et SRV lors de la configuration, Inbox Classic utilise DNS sur HTTPS (Cloudflare, puis Google). La résolution des noms de serveurs utilise toujours le service DNS du système. Il essaie aussi le fichier autoconfig de votre fournisseur et la liste de fournisseurs de Thunderbird (ISPDB). Les requêtes autoconfig peuvent contenir votre adresse e-mail. Pour Exchange, il interroge Microsoft Autodiscover, qui ne reçoit votre mot de passe que s'il le demande en HTTPS. Un serveur sans chiffrement n'est jamais choisi.
  • La connexion via le navigateur, avec OAuth 2.0 et PKCE, auprès de Google, de Microsoft ou du fournisseur de votre application de connexion. Le navigateur revient vers Inbox Classic sur cet ordinateur uniquement.
  • Les logos des marques (BIMI), depuis l'adresse HTTPS de la marque quand le message ne contient pas le logo et qu'aucune copie conservée ne peut être réutilisée. Les logos téléchargés sont conservés et réutilisés, même après un redémarrage du programme. Cela n'arrive que si le message a passé le contrôle DMARC de votre serveur de messagerie et que celui-ci a approuvé le logo.
  • Les images d'Internet, lorsque vous les demandez ou les autorisez pour le domaine de l’expéditeur. Cette autorisation ne s’applique pas au courrier indésirable ni aux parties chiffrées.
  • Le désabonnement, seulement après votre confirmation, même si un agent la propose. Une demande en un clic (RFC 8058) n'est envoyée que si une signature DKIM valide couvre les en-têtes nécessaires au désabonnement. Cela ne garantit pas la fiabilité de l’expéditeur.
  • Les clés de chiffrement sont recherchées lorsqu’il manque la clé d’un destinataire pour chiffrer un message ou lorsque vous lancez une recherche de clé. Pour une recherche par adresse e-mail, le domaine de cette adresse est interrogé en premier (Web Key Directory). Si nécessaire, l’adresse est ensuite envoyée à keys.openpgp.org, sauf si vous avez désactivé cette recherche. Une recherche par empreinte ou identifiant de clé transmet cet identifiant à keys.openpgp.org plutôt qu’une adresse.
  • Les mises à jour, depuis inboxclassic.com, pour savoir si une nouvelle version est disponible, lorsque les vérifications sont activées ou que vous en demandez une.

Les codes de connexion ne sont proposés que si l'en-tête Authentication-Results / ARC-Authentication-Results de votre fournisseur indique que le domaine a signé le message (DKIM). Cela ne demande aucune connexion particulière.
