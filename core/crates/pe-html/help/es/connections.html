Las conexiones que hace Inbox Classic

Adónde se conecta Inbox Classic y por qué, para quienes quieran conocer los detalles técnicos.

  • Sus servidores de correo, por IMAP para leer el correo y por SMTP para enviarlo. Las conexiones se cifran con TLS, y el certificado de cada servidor se comprueba con los certificados en los que confía su sistema. Inbox Classic rechaza un servidor sin cifrado, salvo que usted elija y lo confirme.
  • Al agregar una cuenta, para buscar sus servidores. Para consultar los registros MX y SRV durante la configuración, Inbox Classic usa DNS sobre HTTPS (Cloudflare y, después, Google). La resolución de los nombres de los servidores sigue usando el servicio DNS del sistema. También prueba el archivo autoconfig de su proveedor y la lista de proveedores de Thunderbird (ISPDB); las solicitudes de autoconfig pueden incluir su dirección de correo. Para Exchange, consulta Microsoft Autodiscover, que solo recibe su contraseña cuando la pide por HTTPS. Nunca se elige un servidor sin cifrado.
  • El inicio de sesión por navegador, con OAuth 2.0 y PKCE, en Google, Microsoft o el proveedor de su aplicación de inicio de sesión. El navegador vuelve a Inbox Classic solo en este equipo.
  • Los logotipos de marca (BIMI), desde la dirección HTTPS de la marca cuando el mensaje no incluye el logotipo y no se puede reutilizar una copia guardada. Los logotipos descargados se guardan y reutilizan, incluso después de reiniciar el programa. Solo ocurre cuando su servidor de correo ha dado por buena la comprobación DMARC del mensaje y ha aprobado el logotipo.
  • Las imágenes de internet, cuando las solicita o cuando están permitidas para el dominio del remitente. Esta autorización no se aplica al correo no deseado ni a los mensajes cifrados.
  • La cancelación de suscripciones, solo cuando usted hace clic en ella. Una solicitud de un solo clic (RFC 8058) se envía solo cuando una firma DKIM válida cubre los encabezados necesarios para solicitar la baja. Esto no garantiza que el remitente sea fiable.
  • Las claves de cifrado se buscan cuando falta la clave de un destinatario al cifrar un mensaje o cuando solicita una búsqueda de claves. Si busca por dirección de correo, se consulta primero el dominio de esa dirección (Web Key Directory). Si hace falta, se envía la dirección a keys.openpgp.org, salvo que haya desactivado esa búsqueda. Si busca por huella digital o identificador de clave, se envía ese dato a keys.openpgp.org en lugar de una dirección.
  • Las actualizaciones, desde inboxclassic.com, para ver si hay una versión nueva cuando las comprobaciones están activadas o usted las solicita.

Los códigos de inicio de sesión solo se ofrecen cuando el encabezado Authentication-Results de su proveedor indica que el dominio firmó el mensaje (DKIM). Esto no necesita ninguna conexión propia.
