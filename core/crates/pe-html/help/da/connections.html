De forbindelser, Inbox Classic opretter

Hvor Inbox Classic opretter forbindelse, og hvorfor, for de teknisk nysgerrige.

  • Dine mailservere, via IMAP for at læse mail og SMTP for at sende den. Forbindelserne krypteres med TLS, og hver servers certifikat kontrolleres mod dem, dit system har tillid til. Inbox Classic afviser en server uden kryptering, medmindre du vælger og bekræfter.
  • Når du tilføjer en konto, for at slå dens servere op. Inbox Classic læser dit domænes DNS-poster via DNS over HTTPS (Cloudflare, derefter Google), aldrig almindelig DNS. Programmet prøver også din udbyders autoconfig-fil og Thunderbirds liste over udbydere (ISPDB). For Exchange spørger det Microsoft Autodiscover, som kun får din adgangskode, når den beder om den via HTTPS. En server uden kryptering bliver aldrig valgt.
  • Login via browser, med OAuth 2.0 og PKCE, hos Google, Microsoft eller udbyderen af din login-app. Browseren vender kun tilbage til Inbox Classic på denne computer.
  • Brandlogoer (BIMI), fra brandets HTTPS-adresse, når meddelelsen ikke selv har logoet med, én gang hver gang Inbox Classic kører. Det sker kun, når din mailserver har godkendt meddelelsens DMARC-kontrol og logoet.
  • Billeder fra internettet, kun når du beder om dem.
  • Afmelding, kun når du klikker på den. En anmodning med ét klik (RFC 8058) sendes kun, når listen har signeret meddelelsen med DKIM.
  • Opdateringer, fra inboxclassic.com, for at se, om der er kommet en ny version.

Loginkoder tilbydes kun, når din udbyders Authentication-Results-header siger, at domænet har signeret meddelelsen (DKIM). Det kræver ingen forbindelse i sig selv.
