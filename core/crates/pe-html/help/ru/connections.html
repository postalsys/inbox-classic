Подключения Inbox Classic

Куда подключается Inbox Classic и зачем: для тех, кому интересны технические подробности.

  • Ваши почтовые серверы: по IMAP для чтения почты и по SMTP для отправки. Соединения шифруются TLS, а сертификат каждого сервера проверяется по сертификатам, которым доверяет ваша система. Inbox Classic отказывается работать с сервером без шифрования, если только вы не выберете и не подтвердите выбор.
  • При добавлении учетной записи, чтобы найти ее серверы. Inbox Classic читает записи DNS вашего домена через DNS over HTTPS (Cloudflare, затем Google), никогда не через обычный DNS. Она также пробует файл автонастройки вашего провайдера и список провайдеров Thunderbird (ISPDB). Для Exchange она обращается к Microsoft Autodiscover, который получает ваш пароль, только если запрашивает его по HTTPS. Сервер без шифрования никогда не выбирается.
  • Вход через браузер с OAuth 2.0 и PKCE в Google, Microsoft или к провайдеру вашего приложения для входа. Браузер возвращается только в Inbox Classic на этом компьютере.
  • Логотипы брендов (BIMI): с HTTPS-адреса бренда, если сообщение не содержит логотип, один раз за каждый запуск Inbox Classic. Это происходит, только если ваш почтовый сервер подтвердил проверку DMARC сообщения и одобрил логотип.
  • Изображения из интернета: только по вашему запросу.
  • Отписка: только когда вы ее нажимаете. Запрос в один щелчок (RFC 8058) отправляется, только если рассылка подписала сообщение с помощью DKIM.
  • Обновления: с inboxclassic.com, чтобы узнать, вышла ли новая версия.

Коды для входа предлагаются, только если заголовок Authentication-Results вашего провайдера сообщает, что домен подписал сообщение (DKIM). Для этого отдельное подключение не нужно.
