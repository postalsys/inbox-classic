Koneksi yang dibuat Inbox Classic

Ke mana Inbox Classic terhubung, dan mengapa, bagi yang ingin tahu detail teknisnya.

  • Server email Anda, melalui IMAP untuk membaca email dan SMTP untuk mengirimnya. Koneksi dienkripsi dengan TLS, dan sertifikat setiap server diperiksa terhadap sertifikat yang dipercaya sistem Anda. Inbox Classic menolak server tanpa enkripsi, kecuali Anda memilih dan mengonfirmasinya.
  • Saat Anda menambahkan akun, untuk mencari servernya. Inbox Classic membaca catatan DNS domain Anda melalui DNS over HTTPS (Cloudflare, lalu Google), tidak pernah melalui DNS biasa. Aplikasi juga mencoba file autoconfig penyedia Anda dan daftar penyedia Thunderbird (ISPDB). Untuk Exchange, aplikasi menanyakan Microsoft Autodiscover, yang menerima kata sandi Anda hanya jika memintanya melalui HTTPS. Server tanpa enkripsi tidak pernah dipilih.
  • Masuk melalui browser, dengan OAuth 2.0 dan PKCE, ke Google, Microsoft, atau penyedia aplikasi masuk Anda. Browser kembali ke Inbox Classic hanya di komputer ini.
  • Logo merek (BIMI), dari alamat HTTPS merek tersebut jika pesan tidak membawa logo yang dapat digunakan dan tidak ada salinan tersimpan yang dapat dipakai ulang. Logo yang diunduh disimpan di cache meskipun aplikasi dimulai ulang. Ini hanya terjadi jika server email Anda meloloskan pemeriksaan DMARC pesan dan menyetujui logonya.
  • Gambar dari internet, jika Anda mengizinkannya, termasuk melalui pengaturan pengirim tepercaya atau unduhan otomatis.
  • Berhenti berlangganan, hanya dengan persetujuan Anda. Permintaan sekali klik (RFC 8058) memerlukan tanda tangan DKIM yang diterima server email Anda dan mencakup kedua header berhenti berlangganan.
  • Kunci enkripsi, saat kunci penerima diperlukan atau Anda memulai pencarian. Pencarian alamat menanyakan domain alamat tersebut (Web Key Directory), lalu keys.openpgp.org jika diaktifkan. Pencarian sidik jari atau ID kunci mengirim pengenal itu ke keys.openpgp.org, bukan alamat. Menerbitkan kunci publik Anda mengirimnya ke keys.openpgp.org dan meminta konfirmasi alamat-alamatnya.
  • Pembaruan, dari inboxclassic.com, untuk melihat apakah versi baru sudah tersedia.

Kode masuk hanya ditawarkan jika penyedia Anda melaporkan tanda tangan DKIM yang valid dari domain kode tersebut atau domain induknya. Inbox Classic membaca hasil ini dari header Authentication-Results atau ARC-Authentication-Results penyedia. Ini tidak memerlukan koneksi tersendiri.
