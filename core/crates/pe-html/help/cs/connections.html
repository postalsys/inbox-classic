Připojení, která Inbox Classic navazuje

Technický přehled míst, kam se Inbox Classic připojuje, a důvodů těchto připojení.

  • Vaše poštovní servery přes IMAP pro čtení pošty a SMTP pro její odesílání. Připojení jsou šifrována pomocí TLS a certifikát každého serveru se ověřuje pomocí certifikátů, kterým důvěřuje operační systém. Inbox Classic odmítne server bez šifrování, pokud nezvolíte a nepotvrdíte to.
  • Při přidání účtu kvůli vyhledání jeho serverů. Inbox Classic čte záznamy DNS vaší domény přes DNS over HTTPS (Cloudflare, pak Google), nikoli pomocí nešifrovaných dotazů DNS. Zkouší také soubor autoconfig vašeho poskytovatele a seznam poskytovatelů Thunderbirdu (ISPDB). U Exchange se dotazuje služby Microsoft Autodiscover. Heslo jí odešle jen tehdy, pokud si je služba vyžádá přes HTTPS. Server bez šifrování se nikdy nevybere.
  • Přihlášení v prohlížeči pomocí OAuth 2.0 a PKCE ke Googlu, Microsoftu nebo k poskytovateli vaší přihlašovací aplikace. Výsledek přihlášení se předává zpět aplikaci Inbox Classic přes místní adresu v tomto počítači.
  • Loga značek (BIMI) z adresy HTTPS značky, pokud zpráva logo neobsahuje a nelze použít uloženou kopii. Stažená loga se ukládají a používají znovu, i po restartu aplikace. Stane se to jen tehdy, když váš poštovní server zprávu ověřil kontrolou DMARC a logo schválil.
  • Obrázky z internetu, pokud je stáhnete ručně nebo povolíte jejich automatické stahování.
  • Odhlášení odběru, jen když na něj kliknete. Přímý požadavek na odhlášení (RFC 8058) se odešle jen při ověřeném podpisu DKIM odesílajícího seznamu.
  • Šifrovací klíče, jen když šifrujete někomu, jehož klíč nemáte: vlastní doména jeho adresy (Web Key Directory), potom keys.openpgp.org, pokud jste to nevypnuli. Odesílá se jen adresa.
  • Aktualizace z inboxclassic.com, aby se zjistilo, zda vyšla nová verze.

Přihlašovací kódy se nabízejí, jen když hlavička Authentication-Results od vašeho poskytovatele uvádí, že doména zprávu podepsala (DKIM). K tomu není potřeba žádné další připojení.
