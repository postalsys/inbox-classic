Připojení, která Inbox Classic navazuje

Kam se Inbox Classic připojuje a proč, pro technicky zvídavé.

  • Vaše poštovní servery přes IMAP pro čtení pošty a SMTP pro její odesílání. Připojení jsou šifrována pomocí TLS a certifikát každého serveru se ověřuje proti certifikátům, kterým váš systém důvěřuje. Inbox Classic odmítne server bez šifrování, pokud nezvolíte a nepotvrdíte to.
  • Při přidání účtu kvůli vyhledání jeho serverů. Inbox Classic čte záznamy DNS vaší domény přes DNS over HTTPS (Cloudflare, pak Google), nikdy přes obyčejné DNS. Zkouší také soubor autoconfig vašeho poskytovatele a seznam poskytovatelů Thunderbirdu (ISPDB). U Exchange se ptá služby Microsoft Autodiscover, která vaše heslo dostane jen tehdy, když si o ně řekne přes HTTPS. Server bez šifrování se nikdy nevybere.
  • Přihlášení v prohlížeči pomocí OAuth 2.0 a PKCE ke Googlu, Microsoftu nebo k poskytovateli vaší přihlašovací aplikace. Prohlížeč se vrací do Inbox Classic jen na tomto počítači.
  • Loga značek (BIMI) z adresy HTTPS značky, když zpráva logo sama nenese, jednou při každém spuštění Inbox Classic. Stane se to jen tehdy, když váš poštovní server zprávu ověřil kontrolou DMARC a logo schválil.
  • Obrázky z internetu, jen když o ně požádáte.
  • Odhlášení odběru, jen když na něj kliknete. Požadavek jedním kliknutím (RFC 8058) se odešle, jen pokud konference zprávu podepsala pomocí DKIM.
  • Šifrovací klíče, jen když šifrujete někomu, jehož klíč nemáte: vlastní doména jeho adresy (Web Key Directory), potom keys.openpgp.org, pokud jste to nevypnuli. Odesílá se jen adresa.
  • Aktualizace z inboxclassic.com, aby se zjistilo, zda vyšla nová verze.

Přihlašovací kódy se nabízejí, jen když hlavička Authentication-Results od vašeho poskytovatele uvádí, že doména zprávu podepsala (DKIM). K tomu není potřeba žádné další připojení.
