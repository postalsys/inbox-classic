As conexões que o Inbox Classic faz

Conheça as conexões de rede usadas pelo Inbox Classic e a finalidade de cada uma.

  • Seus servidores de e-mail, por IMAP para ler os e-mails e por SMTP para enviá-los. As conexões são criptografadas com TLS, e o certificado de cada servidor é verificado com base nos certificados em que o seu sistema confia. O Inbox Classic recusa um servidor sem criptografia, a não ser que você escolha e confirme.
  • Quando você adiciona uma conta, para procurar os servidores dela. O Inbox Classic lê os registros DNS do seu domínio por DNS over HTTPS (Cloudflare e depois Google), nunca por DNS simples. Ele também tenta o arquivo autoconfig do seu provedor e a lista de provedores do Thunderbird (ISPDB). Para o Exchange, ele consulta a Descoberta Automática da Microsoft, que só recebe a sua senha quando a pede por HTTPS. Um servidor sem criptografia nunca é escolhido.
  • Login pelo navegador, com OAuth 2.0 e PKCE, no Google, na Microsoft ou no provedor do seu aplicativo de login. O navegador volta para o Inbox Classic apenas neste computador.
  • Logotipos de marcas (BIMI), a partir do endereço HTTPS da marca quando a mensagem não inclui o logotipo e não é possível reutilizar uma cópia salva. Os logotipos baixados são salvos e reutilizados, mesmo depois que o aplicativo é reiniciado. Isso só acontece quando o seu servidor de e-mail aprovou a verificação DMARC da mensagem e o logotipo.
  • Imagens da internet, quando você autoriza o carregamento, inclusive pelas opções de remetentes confiáveis ou carregamento automático.
  • Cancelar inscrição, só quando você clica nesse botão. Uma solicitação com um clique (RFC 8058) só é enviada quando a lista assinou a mensagem com DKIM.
  • As chaves de criptografia são procuradas quando falta a chave de um destinatário para criptografar uma mensagem ou quando você inicia uma busca de chaves. Em uma busca por endereço de e-mail, o Inbox Classic consulta primeiro o domínio desse endereço (Web Key Directory). Se necessário, envia o endereço para keys.openpgp.org, desde que essa busca esteja ativada. Em uma busca por impressão digital ou ID da chave, envia esse identificador para keys.openpgp.org em vez de um endereço de e-mail.
  • Atualizações, a partir de inboxclassic.com, para ver se saiu uma versão nova.

Os códigos de login só são oferecidos quando o cabeçalho Authentication-Results do seu provedor indica que o domínio assinou a mensagem (DKIM). Essa verificação não exige uma conexão adicional.
