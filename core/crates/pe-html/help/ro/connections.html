Conexiunile pe care le face Inbox Classic

Unde se conectează Inbox Classic și de ce, pentru cei interesați de detalii tehnice.

  • Serverele dvs. de e-mail, prin IMAP pentru citire și SMTP pentru trimitere. Conexiunile sunt criptate cu TLS, iar certificatul fiecărui server este verificat față de cele în care are încredere sistemul. Inbox Classic refuză un server fără criptare, cu excepția cazului în care alegeți și confirmați.
  • Când adăugați un cont, pentru a-i căuta serverele. Inbox Classic citește înregistrările DNS ale domeniului prin DNS over HTTPS (Cloudflare, apoi Google), niciodată prin DNS simplu. Încearcă și fișierul autoconfig al furnizorului și lista de furnizori a Thunderbird (ISPDB). Pentru Exchange, întreabă Microsoft Autodiscover, care primește parola doar când o cere prin HTTPS. Un server fără criptare nu este ales niciodată.
  • Conectarea prin browser, cu OAuth 2.0 și PKCE, la Google, Microsoft sau furnizorul aplicației dvs. de conectare. Browserul revine doar la Inbox Classic de pe acest computer.
  • Siglele mărcilor (BIMI), de la adresa HTTPS a mărcii când mesajul nu conține sigla, o singură dată la fiecare rulare a Inbox Classic. Acest lucru se întâmplă doar când serverul dvs. de e-mail a trecut mesajul prin verificarea DMARC și a aprobat sigla.
  • Imaginile de pe internet, doar când le cereți.
  • Dezabonarea, doar când faceți clic pe ea. O cerere cu un singur clic (RFC 8058) este trimisă doar când lista a semnat mesajul cu DKIM.
  • Actualizările, de la inboxclassic.com, pentru a vedea dacă a apărut o versiune nouă.

Codurile de conectare sunt oferite doar când antetul Authentication-Results al furnizorului spune că domeniul a semnat mesajul (DKIM). Pentru aceasta nu este nevoie de o conexiune separată.
