Conexiunile pe care le face Inbox Classic

Unde se conectează Inbox Classic și de ce, pentru cei interesați de detalii tehnice.

  • Serverele dvs. de e-mail, prin IMAP pentru citire și SMTP pentru trimitere. Conexiunile sunt criptate cu TLS, iar certificatul fiecărui server este verificat față de cele în care are încredere sistemul. Inbox Classic refuză un server fără criptare, cu excepția cazului în care alegeți și confirmați.
  • Când adăugați un cont, pentru a-i căuta serverele. Inbox Classic caută înregistrările MX și SRV pentru configurare prin DNS over HTTPS (Cloudflare, apoi Google). Pentru numele serverelor la care se conectează se folosește și rezolvarea DNS obișnuită a sistemului. Încearcă și fișierul autoconfig al furnizorului, căruia îi poate transmite adresa dvs. de e-mail, și lista de furnizori a Thunderbird (ISPDB). Pentru Exchange, întreabă Microsoft Autodiscover, care primește parola doar după o cerere de autentificare HTTP Basic prin HTTPS. Un server fără criptare nu este ales niciodată.
  • Conectarea prin browser, cu OAuth 2.0 și PKCE, la Google, Microsoft sau furnizorul aplicației dvs. de conectare. Browserul revine doar la Inbox Classic de pe acest computer.
  • Siglele mărcilor (BIMI), de la adresa HTTPS a mărcii când mesajul nu conține sigla, dacă nu există o copie locală actuală. Copia este păstrată între porniri și poate fi actualizată după 30 de zile; o încercare nereușită poate fi repetată după o zi. Solicitarea poate dezvălui momentul accesării și adresa IP. Acest lucru se întâmplă doar când serverul dvs. de e-mail a confirmat că mesajul a trecut verificarea DMARC și a aprobat sigla.
  • Imaginile de pe internet, când le cereți sau când setările permit încărcarea automată, inclusiv pentru expeditorii de încredere confirmați. Părțile criptate cer permisiunea explicită de fiecare dată.
  • Dezabonarea, doar cu acordul dvs. O cerere cu un singur clic (RFC 8058) este trimisă doar când lista a semnat mesajul cu DKIM.
  • Cheile de criptare, când criptați pentru un destinatar a cărui cheie nu o aveți sau când cereți căutarea unei chei. Pentru o adresă, este interogat mai întâi domeniul ei (Web Key Directory), apoi keys.openpgp.org dacă opțiunea este activată. Se trimite adresa căutată, nu conținutul mesajului. O căutare după amprenta sau identificatorul cheii transmite acel identificator. Publicarea unei chei transmite cheia publică și adresele pentru care se cere confirmarea.
  • Actualizările, de la inboxclassic.com, pentru a vedea dacă a apărut o versiune nouă, automat dacă opțiunea este activată sau la cerere.

Codurile de conectare sunt oferite doar când antetul Authentication-Results al furnizorului spune că domeniul a semnat mesajul (DKIM). Pentru aceasta nu este nevoie de o conexiune separată.
