Anslutningarna Inbox Classic gör

Vart Inbox Classic ansluter, och varför, för den tekniskt nyfikne.

  • Dina e-postservrar, via IMAP för att läsa e-post och SMTP för att skicka den. Anslutningarna krypteras med TLS, och varje servers certifikat kontrolleras mot dem som ditt system litar på. Inbox Classic vägrar en server utan kryptering, om du inte väljer och bekräftar.
  • När du lägger till ett konto, för att hitta dess servrar. Inbox Classic läser domänens DNS-poster via DNS över HTTPS (Cloudflare, sedan Google), aldrig vanlig DNS. Det provar också leverantörens autoconfig-fil och Thunderbirds lista över leverantörer (ISPDB). För Exchange frågar det Microsoft Autodiscover, som bara får ditt lösenord när det ber om det via HTTPS. En server utan kryptering väljs aldrig.
  • Inloggning i webbläsaren, med OAuth 2.0 och PKCE, hos Google, Microsoft eller leverantören av din inloggningsapp. Webbläsaren återvänder bara till Inbox Classic på den här datorn.
  • Varumärkeslogotyper (BIMI), från varumärkets HTTPS-adress när meddelandet inte har med logotypen, en gång varje gång Inbox Classic körs. Det sker bara när din e-postserver har godkänt meddelandets DMARC-kontroll och logotypen.
  • Bilder från internet, bara när du ber om dem.
  • Avsluta prenumeration, bara när du klickar på det. En begäran med ett klick (RFC 8058) skickas bara när listan har signerat meddelandet med DKIM.
  • Uppdateringar, från inboxclassic.com, för att se om en ny version finns.

Inloggningskoder erbjuds bara när leverantörens huvud Authentication-Results säger att domänen har signerat meddelandet (DKIM). Det kräver ingen egen anslutning.
